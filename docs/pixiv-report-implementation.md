# Pixiv 通報機能の実装メモ

## pixez-flutter の解析結果

参照したローカルソースでは、`lib/page/report/report_items_page.dart` は理由一覧を表示しますが、選択した理由をコールバックに渡していません。

- `lib/page/picture/illust_lighting_page.dart`: Android の送信操作は `muteStore.insertBanIllusts` を実行します。
- `lib/page/user/users_page.dart`: 送信操作は `muteStore.insertBanUserId` を実行します。
- `lib/page/comment/comment_page.dart`: 通報画面への導線がありますが、この画面自体に Pixiv API 送信処理はありません。

この実装から Pixiv 運営への送信 API や理由コードは確認できません。ローカルの非表示処理を送信成功として流用しないようにしています。

## Palleria の変更

作品詳細とユーザープロフィールの「問題を報告」から、対象と詳細情報を確認できる共通ダイアログを開きます。明示的な送信操作で既存の ViewModel → Repository → PixivApiClient の経路を呼びます。

既存 API は `v1/illust/report` と `v1/user/report` への認証付き POST です。今回、エンドポイントや認証更新処理は変更していません。理由コードは参照元で確認できないため `type_of_problem` を追加せず、入力した内容を `message` として渡します。空白のみの入力は省略します。

送信中は送信・キャンセル操作を無効にし、成功時のみ閉じます。失敗時は入力を保持し、再試行と公式サイトを開く操作を提供します。公式サイトでの送信は、利用者が対象ページの「問題を報告」から行います。ブラウザー側のログインが必要な場合があります。

## 検証の範囲

実在する作品・ユーザーへの通報は送信していません。既存エンドポイントが現在の Pixiv サーバーで受理されることや、運営による受付・処理は未検証です。pixez-flutter の解析のみではこの仕様は確定できません。

手動確認項目:

1. 作品詳細とプロフィールのメニューから対象に対応した確認画面が開く。
2. キャンセルでは送信やミュートを行わない。
3. 送信中に連打してもダイアログから追加の送信を開始しない。
4. 通信エラー時に入力が残り、再試行できる。
5. 失敗後のブラウザー操作で対象の作品／ユーザーページが開く。

公式の通報案内: [迷惑行為・違反作品に対する対応](https://www.pixiv.help/hc/ja/articles/235645027)
